# プロダクト要求定義書

## プロダクトビジョンと目的

Claude Code / Claude API・モデルなど、Anthropic公式ドキュメントをローカルにMarkdownとしてミラーし、gitで管理する。これにより、Claude Codeが日々の作業の中で公式の一次情報を正確に参照できるようにし、古い学習知識や推測に基づく誤回答を減らす。

さらに、取得したドキュメント群は全社ナレッジ共有リポジトリ（`project_tri/knowledge-share-repo`）にも反映し、`knowledge-share-app`経由で非エンジニアを含む全社員が閲覧・検索できる状態にする。

いわば「Claude Code自身のための、最新かつ正確なリファレンス」であると同時に、「全社員向けのClaude公式ドキュメント棚」を用意するプロジェクトである。

## ターゲットユーザーと課題・ニーズ

- **一次ユーザー**: 筒井本人（Claude Codeからの参照が主目的）
- **二次ユーザー**: 全社員（`knowledge-share-repo`経由での閲覧。非エンジニアも含む）
- **課題**:
  - Claude Codeの学習知識には鮮度の限界があり、新機能や仕様変更を反映しきれないことがある
  - 質問のたびに公式サイトを人手で調べるのは手間
  - 既存の`doc-guide`スキルは要約ノート生成が目的で、細部を保持した忠実なリファレンスには使えない
  - 社内でClaude Code / Claude APIについて調べたい人が、都度英語の公式サイトを探しに行っている
- **ニーズ**:
  - Claude Codeが自律的に（またはワンコマンドで）最新の公式ドキュメントを参照できる状態を、手間なく維持したい
  - 収集したドキュメントを、社内の誰でも検索・閲覧できる場所（knowledge-share-repo）にも展開したい

## 主要な機能一覧

| 機能 | 概要 |
|---|---|
| 一括ミラー同期 | 登録済みソース（`llms-full.txt`）から全ページを取得し、ページ単位のMarkdownファイルに分割保存する |
| 個別ページ取得 | 特定URLを指定して1ページだけ取得・追加できる |
| 差分検知とコミット | 前回取得時との内容差分を検知し、変更があったファイルのみ更新してgitコミットする |
| ソースの拡張 | 設定ファイルにソースを1行追加するだけで、新しいドキュメント群を対象に追加できる |
| 定期自動更新 | cronによる定期実行で、ドキュメントの鮮度を自動的に保つ |
| 索引生成 | 取得済み全ファイルの一覧と最終更新日時をまとめた索引を自動生成する |
| 全社共有リポジトリへの公開 | 取得済みドキュメントを`knowledge-share-repo`の新カテゴリ（`claude-docs/`）にコピーし、`metadata.yaml`を自動生成・更新する。実際のgit pushは明示的なコマンド実行時のみ行う（自動同期とは切り離す） |

## 成功の定義

- Claude Codeが本リポジトリ内のMarkdownを参照することで、Claude Code / API・モデルに関する質問に公式仕様どおり正確に回答できる
- ドキュメントの取得・更新に人手の介入がほぼ不要（初期登録以降は自動更新で鮮度を維持）
- 新しいドキュメントソースの追加が低コストで行える
- 全社員が`knowledge-share-app`経由でClaude公式ドキュメントを検索・閲覧できる

## ビジネス要件

個人利用のローカルツールであり、収益・課金要件はない。運用コストを最小限に抑えること（追加インフラや有料サービスに依存しない）を優先する。

## ユーザーストーリー

- 筒井として、Claude Codeに新機能や設定方法を尋ねたとき、公式ドキュメントに基づいた正確な回答を得たい。そのために、ローカルに最新のドキュメントミラーを持ちたい。
- 筒井として、気になった公式ページのURLを渡すだけで、すぐにローカルの参照資料に追加したい。
- 筒井として、`settings.json`・`CLAUDE.md`・hooks・スキルなどClaude Codeの設定ファイルを更新するとき、最新の公式仕様をローカルのミラーで確認しながら、勘や古い記憶に頼らず正確に設定したい。
- 筒井として、日々の運用に手間をかけず、ドキュメントが自動的に最新化されている状態を保ちたい。
- 筒井として、将来別の公式ドキュメント（MCP仕様など）を追加したくなったときに、設定を少し足すだけで対応できるようにしたい。
- 筒井として、収集したドキュメントを`knowledge-share-repo`に反映する前に内容を確認し、意図したタイミングで全社に公開したい。
- 社員として、Claude CodeやClaude APIについて知りたいとき、英語の公式サイトを探しに行かなくても`knowledge-share-app`で検索すれば見つかる状態でありたい。

## 受け入れ条件

- [ ] Claude Code公式ドキュメント（code.claude.com/docs）とAPI/モデル公式ドキュメント（platform.claude.com/docs）の全ページを取得し、ページ単位のMarkdownファイルとして保存できる
- [ ] 指定した1つのURLを個別に取得・保存できる
- [ ] 各Markdownファイルに取得元URLと取得日時が記録されている
- [ ] 再実行時、内容に変更のあったファイルのみ更新され、変更点がgitコミットされる
- [ ] 新しいドキュメントソースを設定ファイルへの追記だけで追加できる
- [ ] 定期実行（cron）により、人手を介さず更新が行われる
- [ ] 取得済みドキュメントを`knowledge-share-repo`の`claude-docs/`カテゴリにコピーし、対応する`metadata.yaml`のエントリが自動生成・更新される
- [ ] `knowledge-share-repo`へのgit pushは自動同期とは独立した、明示的なコマンド実行時にのみ行われる

## 機能要件

- 対象サイトの`llms-full.txt`（全ページ結合Markdown）を取得し、`# タイトル` + `Source: URL` の2行区切りパターンでページ単位に分割できること
- 個別ページ取得時は、対象URL末尾に`.md`を付与した生Markdownエンドポイントを利用すること
- 各ファイルにfrontmatter（`source_url`, `fetched_at`, `content_hash`）を付与すること
- 取得内容のハッシュ値を比較し、変更があった場合のみファイルを上書き・git commitすること
- ソース定義は`sources.yaml`等の設定ファイルで管理し、コード変更なしに追加・削除できること
- 全ファイルの一覧・最終更新日時をまとめた索引（`INDEX.md`）を自動生成すること
- 公開コマンド実行時、`content/`配下の対象ファイルを`knowledge-share-repo/claude-docs/`にコピーし、`knowledge-share-repo`の運用ルールに従って`metadata.yaml`（`path`, `title`, `description`, `tags`, `updated_at`, `owner`）を生成・更新すること
- `knowledge-share-repo`への`git add` / `commit` / `push`は、公開コマンドを明示的に実行したときのみ行うこと（`claude-docs`側の自動同期・自動commitとは別プロセスとする）

## 非機能要件

- **鮮度**: 少なくとも週1回、可能であれば毎日、定期同期が走ること（頻度は運用しながら調整）
- **可搬性**: 特別な有料サービス・外部インフラに依存せず、ローカル環境とcronのみで完結すること
- **安全性**: 取得は公式ドキュメントの読み取り専用アクセスに限定し、認証情報や機密情報を扱わないこと。`git push --force`等の破壊的操作は行わないこと
- **公開範囲の妥当性**: `knowledge-share-repo`に置くのは公式ドキュメントのミラーのみとし、個別プロジェクトの機密情報を混入させないこと（`knowledge-share-repo`の運用ルールに準拠）
- **可観測性**: 同期の成功・失敗、更新されたファイル数がログまたはコミットメッセージから追えること
- **拡張性**: 新しい公式ドキュメントソース（例: MCP仕様、Claude Agent SDKなど）を将来追加しやすい設計であること
